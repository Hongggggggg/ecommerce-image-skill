## 可选图片类型

用户可以指定任意组合、数量和顺序。未指定时，Agent 根据商品资料主动推荐 7～9 张，不机械补齐固定模板。

| 图片类型 | 解决的购买问题 | 选用条件 |
|---|---|---|
| 平台合规主图 | 我买到的是什么 | 按平台首图规则；通常必选 |
| 营销首图 / 商品封面 | 为什么值得继续看 | 渠道允许营销文字时推荐 |
| 核心卖点图 | 核心优势为何成立 | 有明确卖点和视觉证据 |
| 实际使用场景图 | 如何使用、比例是否真实 | 有合理人物/空间/动作关系 |
| 场景氛围图 | 是否符合我的生活方式 | 情绪与生活方式影响购买时 |
| 商品细节图 | 材质、工艺或关键结构是什么 | 有可见且重要的局部证据 |
| 多角度图 | 其他表面或接口长什么样 | 复杂结构且不误导数量 |
| 尺寸 / 容量 / 尺码图 | 是否适合空间、身体或用途 | 有完整准确参数 |
| 详细规格 / 参数图 | 是否满足技术条件 | 参数较多且影响购买 |
| 兼容 / 适配图 | 能否与我的设备或物品配合 | 有准确兼容清单或尺度 |
| 效果 / 状态对比图 | 一个状态变化有什么差异 | 有同尺度同视角的真实依据 |
| 工艺制作图 | 为什么可信或耐用 | 有真实工艺资料，不凭空编造 |
| 配件 / 赠品 / 包装清单 | 我会收到什么 | 内容物和数量已确认 |
| 使用步骤图 | 如何使用、安装或收纳 | 2～4 个已确认连续步骤 |
| 系列展示图 | 有哪些颜色、尺寸或 SKU | 变体真实且不会误导库存 |
| 商品成分 / 结构分解图 | 由什么组成、怎样工作 | 成分或结构资料完整 |
| 品牌故事图 | 为什么信任这个品牌 | 用户提供真实品牌资产 |
| 售后保障图 | 风险如何降低 | 有明确政策与适用地区 |
| 使用建议 / 注意事项图 | 怎样获得合适体验 | 有必要、真实且可读的信息 |

推荐时分三组：

1. **建议保留**：平台硬要求或当前购买决策不可缺少。
2. **按证据可选**：资料与视觉证据足够时才加入。
3. **不建议 / 资料不足**：与商品无关、证据不足或会重复前图。

必须单独确认首图是平台干净主图、营销首图还是两者都要。两者都要时应作为两个不同用途文件，不混用。平台具体要求读取 [平台与发布规则](platform-rules.md)。

## 从说服链路选择图片

不要按素材类型机械凑图。先组织：

1. **抓眼**：识别商品并建立兴趣。
2. **相关**：连接真实需求或使用时刻。
3. **证明**：用结构、动作、局部、尺度或机制证明卖点。
4. **想象**：展示商品进入真实生活后的状态。
5. **消疑**：回答尺寸、兼容、材质、包装或步骤问题。
6. **收束**：用包装内容、步骤、对比或第二场景完成判断。

每张图标记所属阶段和浏览推进句。

## 购买任务、异议与可选动机

套图角色确定前，先从商品事实卡读取 `shopper_job`、主要购买异议、信息不确定性和退货风险驱动因素。每张图都必须填写：

- `shopper_job`：本图帮助顾客完成的具体购买或使用判断。
- `objection_resolved`：本图要消除的一个主要疑虑。
- `return_risk_reduced`：本图降低的尺寸、兼容、数量、材质、使用或预期差异风险。

字段必须存在；确实不适用时写 `NONE + 理由`，不得虚构异议或退货风险来填表。平台干净主图通常聚焦商品识别和销售配置，可以把不适用项写为 `NONE`；后续图应优先覆盖尚未解决的真实异议，避免只重复同一卖点。

卖点、机制、性能或差异解释图可使用 FABE：`Feature → Advantage → Benefit → Evidence`。其中 `Advantage` 只有在真实比较或明确设计优势有证据时才填写，否则固定写 `NOT_ESTABLISHED`；不得为了补齐链路制造竞品劣势。尺寸、步骤、包装等自明消疑图不强制使用 FABE。

生活方式、品牌感或情绪决策明显时，可以记录一个主要动机，例如便利、信心、归属、品质认同或生活方式向往。动机只用于选择场景和语气，不构成用户心理事实或宣称；尺寸、步骤、包装等任务不强制填写。

## 一图一个主决策任务

每张图只解决一个主要购买问题，但可以包含服务该问题的多个从属事实：

| 图片角色 | 主决策任务 | 允许的从属信息与信息密度 |
|---|---|---|
| 平台干净主图 | 我买到的是什么 | 无文字、无营销组件；只呈现符合平台要求的商品、颜色、数量和包装状态 |
| 营销首图 | 为什么值得继续看 | `headline=1`，逐字包含通用产品名称；`subtitle=1`，作为价值说明；证据表达 `1..2` 组且至少 1 组完整 `label + detail`；组件 `0..1`。一个核心证据必须直接进入主构图，标签和说明与其绑定 |
| 卖点图 | 这个卖点如何成立 | `headline=0..1`；至少 1 组完整 `label + detail`，默认组织 2 组、总数 `1..3`；每条绑定可见证据。允许充分的卖点标签和详细说明，不得只有大标题 |
| 功能使用场景 | 如何操作、接触、适配或摆放 | `headline=0..1`；至少 1 组完整 `label + detail`，可增加第 2 组同任务说明，不得无字。主画布必须显示动作和接触/摆放点 |
| 纯生活方式场景 | 是否符合我的生活方式 | `headline=0..1`、`label/detail=0..2`；允许使用卖点标签和详细说明。只有通过本文件的无字例外条件才可 `文字=NONE` |
| 尺寸 / 容量图 | 是否适合我的空间或使用 | 每个有效尺寸或容量至少有一个贴线 `dimension_label`；可另加 `label/detail=0..2` 解释容量、适配或使用意义；不得使用 `SIZE`、`DIMENSIONS`、`SIMULATED DIMENSIONS` 等无信息大标题；模拟状态不进入成图 |
| 细节 / 材质图 | 关键结构或材质是什么 | `headline=0..1`；至少 1 组完整 `label + detail`，默认组织 2 组、总数 `1..3`；说明与真实局部、材料或结构绑定。允许充分详解，不得只有大标题 |
| 步骤图 | 如何使用或安装 | 2～4 个连续步骤；每步必须有一个 `action_label`，可另有 `headline=0..1` 与 `label/detail=0..2` 解释关键动作，不得只用编号或披露 |
| 包装清单 | 我会收到什么 | 每个物品组必须有贴近对应物品的 `item_label` 和准确数量；`headline=0..1`，可用 `label/detail=0..2` 解释套装关系或必要说明 |
| 对比 / 状态图 | 一个可验证变量有何差异 | 两侧各有 `state_label`，并有 `detail=1..2` 说明唯一变量；可增加与状态证据绑定的短 `label`，保持同尺度、同视角 |

同一画面出现多个事实不自动构成信息过载。只有两个无关问题、多个同权重卖点或互相竞争的阅读路径同时存在时才拆图。

营销首图使用 1 条必填价值说明 `subtitle`；其他图片不把详解误标为第二主标题，而是使用 `label/detail`。所有非平台合规图片均允许按主任务加入卖点标签和详细说明。营销首图、卖点图、细节图和材质图默认至少有 1 组完整 `label + detail`；这里的加号表示同一证据的配对，不是“二选一”或数量相加。不能再用“按需”把它降为只有大标题。若没有足够事实支持说明，改成中性可见描述、换成有证据的图片任务，或对非首图使用下述无字例外；不得用空泛文案补位。

“短描述词＋短事实说明”不是固定视觉模板；一张图可以在完整证据对之外增加单独 `label` 或 `detail`，营销首图、卖点图、细节图和材质图的总证据表达数通常为 `1..3`。场景、尺寸、步骤、包装、兼容和状态图也可按信息增量使用。采用卡片还是直接标注按证据位置决定；详细语义和词数只读取 [转化设计系统](conversion-design-system.md)。视觉主导不等于无字：1～2 条清晰、贴近证据的表达仍可让商品、动作或场景主导画面。

卖点、细节或材质图只有同时满足以下条件才可使用 `visual_only_exception`：

1. `headline=0`，不能留下“仅大标题”；模拟/不可发布状态文字默认不得出现在成图中。
2. 核心证据在 200～240 px 下可辨，且无需文字即可准确识别具体部位、材料或结构关系，而不是只认出商品。
3. 策划卡记录 `exception_code=VISUAL_SELF_EVIDENT`、可见证据、1 秒理解结论和删除文字后仍成立的理由。
4. 不突破本套非干净主图无字上限，并通过联系表复核。

## 7/8/9 张文字覆盖硬门槛

模拟状态、AI 来源和发布资格只记录在非像素台账。用户未明确要求时，`DESIGN PREVIEW`、`SIMULATED`、`NOT PUBLISHABLE`、`SIMULATED DIMENSIONS` 等状态文字不得出现在成图中；用户明确批准的可见披露仍记为 `disclosure/decorative`，不计入商品信息文案。商品信息文案只统计 `headline`、`subtitle`、`label`、`detail`、`dimension_label`、`action_label`、`item_label`、`state_label`。

| 套图总张数 | 含 1 张干净主图时：至少含商品信息文案的图片数 | 不含干净主图时：至少含商品信息文案的图片数 | 非干净主图无字上限 | 至少含 `label/detail` 的证据图片数 |
|---:|---:|---:|---:|---:|
| 7 | 5 | 6 | 1 | 3 |
| 8 | 6 | 7 | 1 | 4 |
| 9 | 7 | 8 | 1 | 4 |

同时满足以下零容忍配额：

- `visible_status_disclosure_images=0`：用户未明确批准时，任何图片都不得出现模拟/不可发布状态小字。
- `headline_only_non_clean=0`：除平台干净主图外，任何图片都不得只有 headline；营销首图也必须有价值说明和完整证据对，其他角色必须有相应的证据、尺寸、动作、物品或状态文字。
- `functional_scene_without_explanation=0`：每张功能使用场景必须有一组贴近动作、接触、适配或摆放证据的 `label + detail`。
- 每套至少 2 张营销图满足 `component=NONE` 且 `evidence_dominant=true`；这两张仍可使用 1～3 条直接绑定证据的 `label/detail`，不能用少字或无字作为“视觉主导”的判据。平台干净主图不计入。
- 无字图仍须记录角色、框架、P/T/E、视觉证据和无字理由；缺少任一字段不算有效例外。

## 场景图文字决策

不要把“画面大致看得懂”当作自动无字。逐张执行：

1. 写出本图相对其他图片新增的决策信息，例如使用人群、真实比例、动作路径、接触位置、摆放方式或适配关系。
2. 判断用户在 180～240 px 缩略图中能否于约 1 秒内准确理解该信息，而不只是认出商品和场景。
3. 测试一条证据表达是否能增加决策信息，或显著降低对动作、接触、适配、方向和使用结果的解释成本。
4. 功能使用场景固定使用 1 组 `label + detail`，直接贴近动作、接触、适配或摆放证据；不得无字，也不得扩成大标题、卡片墙或副标题。
5. 纯生活方式场景若说明没有信息增量，可采用无字方案，并在策划单写明 `LIFESTYLE_SELF_EVIDENT` 与无字理由；不得为了有留白而加入情绪口号、重复画面内容或泛化形容词。

纯生活方式场景只有同时满足以下条件才可无字：画面自身提供明确的人群、比例、情境或生活方式增量；相关功能已由其他图片解释；删除文字不会让用户误解本图的独特任务；策划卡记录 `exception_code=LIFESTYLE_SELF_EVIDENT` 和 1 秒理解结论。功能使用场景固定至少加入一组 `label + detail`，并在主画布显示动作和接触/摆放点；小窗内的动作不能替代主画布证据。无字场景只有确实提供独立决策信息时才可占用全套唯一的非干净主图无字名额，不能作为凑配额的装饰图。

对比图按证据选择，不是默认收束角色。产品与市场产品对比需要真实竞品资料或明确测试依据，只比较一个变量且不使用竞品 Logo；否则优先改用商品自身状态、结构或兼容证明，不虚构“普通产品”或“市场平均”。

## 图片角色到框架系列

本表只负责把图片角色和主决策任务路由到框架系列；每个框架的完整定义只读取 [框架库](framework-library.md)。

| 图片角色 / 决策任务 | 优先系列 | 常用框架 | 排除提示 |
|---|---|---|---|
| 营销封面 / 为什么继续看 | H | H01、H02、H04 | H03 小型微距窗不用于首图；合规 MAIN 不参与竞争 |
| 功能如何成立 | P | P01、P02、P03、P04 | 没有证据时不选证明类 |
| 如何进入真实生活 | L | L01、L02、L03 | 不为填空虚构人物或场景 |
| 是否适合尺寸或设备 | D | D01、D02 | 缺准确尺寸或兼容资料时降级 |
| 如何使用、会收到什么 | S | S01、S02 | 数量和步骤必须已确认 |

营销首图的 3 个候选优先使用 H01、H02、H04；H04 的主场景证据区必须与画面边缘相连并形成大尺度分区，允许的单个从属组件不能取代该主证据区。H03 主体＋微距默认用于后续细节或卖点图，不参与营销首图竞争。后续图片可跨系列选候选。Amazon MAIN 与 TikTok Shop 干净首图使用平台辅助网格，不使用营销框架。

角色路由只是候选入口，不是配额轮换表。框架锁定前必须同时验证图片角色、主决策任务、证据类型和框架原生 P/T/E 拓扑；若框架的自然结构不能承载本图证据，不得为了框架数量或跨 SKU 差异硬用，改选其他框架或 `X01`。

## 逐图策划卡与生成许可

生成前为每张图填写一行策划卡。平台干净主图可使用平台网格并将 `T/E` 写为 `NONE`；其他图片任一必填字段为空即 `generation_ready=false`，不得生成：

- 平台、渠道、图片角色和目标市场。
- 主决策任务、主结论、说服阶段和浏览推进句。
- `shopper_job`、`objection_resolved`、`return_risk_reduced`；不适用时必须写 `NONE + 理由`。
- 已确认事实和禁止推断内容。
- `claim_ids`：本图每条客户可见事实、数字、数量、材质、兼容、性能、比较、认证、效果或包装内容表述对应的声明 ID；平台干净主图仍须关联商品身份、销售变体和数量依据。仅允许使用 `VERIFIED`，或已满足全部限定条件的 `CONDITIONAL` 声明。
- FABE：卖点、机制、性能或差异解释图按需填写；无证据支持优势时写 `Advantage:NOT_ESTABLISHED`。其他角色写 `NOT_REQUIRED`。
- 主要动机：生活方式、品牌感或情绪决策明显时填写；其他角色写 `NOT_REQUIRED`。
- 框架 ID 或 `X01`、框架家族、适配理由和主要风险。
- 可选组件 ID 和使用理由；没有必要时明确写 `NONE`。
- 相对静态示例至少 3 项 SKU 专属变化。
- 非文字视觉证据。
- 商品位置、占比、视角、机位和镜头距离。
- `P` 商品区、`T` 文字区、`E` 证据区的画布位置与占比；无文字或无独立证据区时也必须写 `T:NONE` 或 `E:MERGED_WITH_P`，不得省略。
- 主轴、三层焦点和视觉动线；视觉动线必须写成 `焦点1 → 焦点2 → 焦点3`。
- 背景、道具、光线、阴影和视觉签名。
- 文字状态、逐字文案、地区版本和主次层级。
- `allowed_text_exact`：允许出现在成图中的全部逐字商品文案，以及用户明确批准的可见披露；模拟/不可发布状态默认不列入。任何未列出的词句均视为模型擅自添加。
- `allowed_text_exact` 中每条事实文案必须能反查策划卡的 `claim_ids`。`claim_id`、状态名、证据来源、`[NEEDS INPUT: ...]` 与其他 `PLACEHOLDER` 只留在非像素台账，不得作为允许文字或图像模型应渲染的内容。
- 场景图额外写明 `场景子类：纯生活方式 / 功能使用 / 场景卖点`、本图信息增量、1 秒理解结论和文字决策；采用 `NONE` 时必须写无字理由。
- 1024×1024 下的主标题、辅助说明、标签和免责声明目标字号；不适用文字明确写 `NONE`。
- 文字角色：营销首图必须有一个价值说明 `subtitle` 和至少一组完整 `label + detail`；其他图的解释文案统一标为 `label`、`detail` 或 `label + detail`，不得因角色省略有信息增量的卖点标签和详细说明。卖点、细节和材质图至少一条标为完整证据对；其余表达写明对应证据、区位、呈现方式和目标字号。只有非首图的完整 `VISUAL_SELF_EVIDENT` 例外可免除该配对。词数与语义以 [转化设计系统](conversion-design-system.md) 为准。
- 字体视觉 DNA 编号、字形类别、字宽、字重、大小写、字距观感、行距、对齐方式、色板关系和文字区；不得只写“使用同款粗体”。
- 整图 AI 提示约束：所有文字、数字、标线、卡片、圆窗和图标均由图像模型生成，不得安排脚本叠加或程序化绘制。
- 必须准确呈现的尺寸、数量、Logo 或包装文字。
- 尺寸图逐项写 `数值｜尺寸语义｜被测边界｜所需视角｜标签位置`；不得只列数字。
- 功能使用场景写明 `主体/使用者｜动作｜接触或摆放点｜商品状态/结果｜文字锚点`，且主画布前四项至少可见 3 项并包含动作与接触/摆放点。
- 与其他图片的框架、主轴、商品区、镜头和证据方式差异。
- 与本批其他 SKU 的结构指纹差异。
- 平台用途和发布资格限制。
- `generation_ready`：只有角色配额、P/T/E、框架、购买任务字段、声明状态、文字角色、证据绑定和组件字段全部通过时写 `true`；存在未解决的 `PLACEHOLDER`、`BLOCKED` 或未满足条件的 `CONDITIONAL` 声明时，不得为受影响图片写 `true`。

营销首图额外写明通用产品名称、包含该名称的主标题逐字文案、必填价值说明逐字文案、1～2 组证据表达及其绑定、一个核心价值主张及依据、货架停止点、标题明确区位、文字块宽高、各角色目标字号、四边至少 8% 的文字安全边距、标题/副标题至少 40 px 内边距、底部 15% 主标题禁区，以及 `组件：NONE` 或一个 C01～C08 组件。品牌名、系列名或纯卖点口号不能替代产品名称。价值说明不能重复产品名；所有 `label/detail` 共同证明同一核心价值，不堆叠无关卖点。

默认由用户确认套图方案。用户明确授权“中间问题自己决策”“不用问”或等效自主执行时，不再停下来询问，但必须保留三个候选、选择理由、淘汰理由、完整策划卡和 `decision_mode=delegated`；该授权只省略提问，不省略规划、框架竞争、记录或 QA。事实缺失仍按宣称规则阻塞或降级。

生成许可只在以下产物全部存在时成立：套图角色表、逐图策划卡、文字覆盖统计、套图多样性统计；批量任务还必须有计划结构指纹分配表。缺少任一产物，不得开始生成第一张非干净主图。观察结构指纹分配表属于交付许可，必须在最终成图完成后建立。

## SKU 结构指纹与批量去重

多个互不相关商品不可共用同一套“8 张位置模板”。生成前先建立计划结构指纹分配表，每个 SKU 一行；生成后还要从最终成图重新建立观察结构指纹表：

```text
SKU｜角色序列｜框架序列｜骨架家族｜主轴分布｜商品区分布｜证据方式｜镜头节奏｜组件节奏｜与最相近 SKU 的差异字段数
```

- `角色序列`：平台图之后实际采用的卖点、场景、细节、尺寸、步骤或包装任务；简单商品可以删换角色，不机械凑齐同一清单。
- `框架序列`：逐图框架 ID；任意两套互不相关 SKU 不得完全相同。
- `主轴分布`：左/右/中心/对角/环绕/连续等主要阅读轴的组合。
- `商品区分布`：主体在哪些画面居中、偏侧、近裁、展开、平铺或进入场景。
- `证据方式`：动作、微距、结构、状态、尺度、空间、第一视角或包装关系。
- `镜头节奏`：全景、中景、近景、微距及视角变化。
- `组件节奏`：`NONE` 与 C01～C08 的使用位置和频率。

同一批任意两套互不相关 SKU 至少在 3 个指纹字段上形成实质差异，且框架序列不得完全相同。左右镜像、只换商品、颜色、背景、道具、场景名或标题不计差异；保留相同 P/T/E 关系、主轴、镜头和证据位置后只替换名词，也判定为同一提示骨架。若产品形态和购买疑虑要求相同框架，仍须在主轴、商品裁切、证据方式、空间层次或组件节奏中重构至少 3 项。计划分配表未完成，或任一行 `差异字段数<3`，整批 `generation_ready=false`。观察分配表未完成或未达到同样差异门槛，整批 `delivery_ready=false`；不得用计划指纹代替成图观察。

## 套图构图多样性硬门槛

每套 7～9 张在生成前按计划值、联系表 QA 后按成图观察值各统计一次；两次均须通过：

- 非干净主图至少使用 4 个不同框架 ID，并覆盖至少 3 个实质不同骨架家族；同一框架不得连续，单一框架全套最多 2 次。
- 至少使用 3 种主轴、3 种证据方式和 3 种镜头距离；镜头距离必须同时包含至少一个整体/场景镜头和一个近景/微距镜头。
- 非干净主图中的典型三分之四角度最多 2 张且不得连续；主商品机械居中的画面最多 2 张且不得连续。
- 连续两张不得同时复用相同的 `骨架家族 + 主轴 + 镜头距离 + 证据方式` 四元组。
- “换背景、换颜色、左右镜像、替换商品或标题”不构成新骨架；`平背景 + 单个居中/三分之四商品 + 独立标题` 且没有 E 区证据的图片数量必须为 0。

## 镜头角度编排

先确定信息任务，再分配最能证明它的视角：

- 平台主图：正面或典型三分之四角度，优先识别。
- 营销首图：典型但有张力的角度，同时保留标题和证据区。
- 卖点或结构图：侧视、低机位、俯视、后上方或局部角度，直接揭示结构。
- 场景图：人物视角、脚部平视、俯拍、侧后方或动态视角，展示真实使用关系。
- 尺寸图：正面、正侧或正俯等接近正投影的测量视角。
- 细节图：局部近景或微距。

典型三分之四角度在非干净主图中最多 2 张且不得连续；同一主视角不得连续。平台干净主图可为识别使用典型三分之四角度，但不构成后续图复用理由。

只有同时满足以下条件才单独设置多角度图：

1. 商品结构复杂，多面信息无法自然分配到其他主题。
2. 多视图共同解决一个尚未覆盖的主决策任务。
3. 不会误导销售数量、变体或包装内容。
4. 不是对前面图片角度的简单重复。

## 品类适配

- 简单单品：保留营销首图，可省略第二卖点图，增加不同视角的细节或场景图。
- 多件套：优先包装清单，并确认每件物品和数量。
- 结构复杂商品：增加结构揭示或步骤图。
- 强尺寸决策商品：尺寸完整后优先尺寸图。
- 涉及健康、食品、儿童或安全：加强宣称证据检查并采用克制表达。

## 方案完成检查

- 每张图是否只有一个主决策任务，且从属信息服务该任务。
- 每张图是否填写 `shopper_job`、`objection_resolved` 和 `return_risk_reduced`，并优先覆盖真实购买疑虑与退货风险；`NONE` 是否附有理由。
- 每条客户可见事实是否有 `claim_id`，且只来自 `VERIFIED` 或已满足全部条件的 `CONDITIONAL` 声明；`PLACEHOLDER`、`BLOCKED` 和内部 ID 是否完全没有进入提示词或成图。
- 卖点、机制、性能或差异解释图使用 FABE 时，`Advantage` 是否有证据；无证据时是否明确为 `NOT_ESTABLISHED`。动机字段是否只在相关图片使用，而没有被当成心理事实。
- 是否形成从抓眼到消疑的说服链路。
- 每个卖点是否有非文字证据。
- 视角是否直接揭示对应信息。
- 7～9 张是否通过文字覆盖表和套图构图多样性硬门槛；所有统计是否为整数而不是“已注意”。
- 批量任务中是否在生成前完成计划结构指纹分配表、生成后完成观察结构指纹分配表；两者任意两套是否至少 3 项实质不同、没有相同框架序列且不存在只替换商品/背景或成图拓扑重复。
- 组件统计是否通过 [可选版式组件](layout-components.md) 的 7/8/9 张上限，营销首图是否不超过 1 个组件、其他营销图是否不超过 2 个，并保留至少 2 张 `component=NONE`、`evidence_dominant=true` 的营销图。
- 营销首图是否有必填价值说明和至少 1 组完整 `label + detail`；卖点、细节和材质图是否全部至少有 1 组完整证据对，或拥有合格 `visual_only_exception`；是否做到 `headline_only_non_clean=0`、`visible_status_disclosure_images=0`。
- 场景图是否正确分类；每张功能使用场景是否有一条贴近证据的表达，纯生活方式无字图是否记录有效理由；尺寸数字是否贴近对应标线且没有无信息标题；步骤图是否使用简短动作标签。
- 对比图是否确有单变量和事实依据；没有时是否已换成自身状态或结构证明。
- 平台合规主图是否为 `组件：NONE`；营销首图是否按策划使用 `0..1` 个组件，且没有未记录、超预算或与主任务无关的组件。
- 营销首图主标题是否明确包含通用产品名称；必填价值说明是否层级低于主标题；是否有 1～2 组与可见证据绑定的卖点标签和详细说明。
- 主标题是否达到移动端字号基线；长文案是否先缩短或重构，而不是整体缩小字号。
- 同套是否保持同一字体视觉 DNA；联系表中重复字母的字形气质、标题宽度、字距观感、行距和对齐是否稳定，颜色变化是否都来自锁定色板且有对比度理由。
- 每张图是否均由图像模型整图生成或整图编辑，没有无字底图后叠字、脚本尺寸线或程序化组件。
- 是否避免通用产品照加独立标题。
- 多视图是否可能造成数量或变体误解。

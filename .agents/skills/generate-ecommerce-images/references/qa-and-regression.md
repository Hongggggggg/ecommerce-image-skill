# 视觉 QA 与回归检查

逐张打开源图和成图目视比对，不要求用户运行检查程序。先按 [生成执行与成图观察验收](execution-and-observed-qa.md) 检查任务绑定并记录成图观察值，再执行零容忍门槛，最后按 [转化设计系统](conversion-design-system.md) 评分。提示词、策划卡和计划统计不能代替最终像素观察。

- 逐张检查
- 套图机械统计

## 套图机械统计

每套生成前依据策划卡填写 `planned_*`，生成后依据全套联系表和全尺寸单图填写 `observed_*`。以下字段必须填写整数、布尔值或明确枚举；不得写“已注意”“大致通过”“尽量不同”。任何必填字段为空，不进入设计评分。

| 字段 | 统计方式 | 通过条件 |
|---|---|---|
| `total_images` | 套图总张数 | 7、8 或 9 |
| `clean_main_count` | 平台干净主图数 | 0 或 1；其文字角色为 0 |
| `product_copy_images` | 至少有一种商品信息文案角色的图片数；披露不计 | 达到 [套图蓝图](image-set-blueprints.md) 对应 7/8/9 配额 |
| `non_clean_textless` | 非干净主图且所有商品信息文案角色均为 0 | `<=1`，且每张有合格例外码 |
| `visible_status_disclosure_images` | 成图出现 DESIGN PREVIEW/SIMULATED/NOT PUBLISHABLE/SIMULATED DIMENSIONS 等状态文字 | 用户未明确批准时为 `0` |
| `headline_only_non_clean` | 除平台干净主图外只有 headline，没有价值说明、label/detail、尺寸、动作、物品或状态文字 | `0` |
| `evidence_copy_images` | 至少有一个证据绑定 label/detail 的图片数 | 达到 [套图蓝图](image-set-blueprints.md) 对应配额 |
| `feature_detail_material_complete_pairs` | 卖点/细节/材质图至少有一组完整 `label + detail` 的数量 | 等于无例外的对应角色图片数 |
| `feature_detail_material_exceptions` | 卖点/细节/材质图无 label/detail 的例外数 | 每项均有 `VISUAL_SELF_EVIDENT`、200 px 证据和理由；同时受无字上限约束 |
| `functional_scenes_total` | 功能使用场景数 | 整数 |
| `functional_scenes_explained` | 有一组 `label + detail` 的功能场景数 | 等于 `functional_scenes_total` |
| `functional_scene_main_canvas_evidence_missing` | 主画布缺动作或接触/摆放点的功能场景数 | `0` |
| `unique_framework_ids` | 非干净主图不同框架 ID 数 | `>=4` |
| `skeleton_families` | 实质不同 P/T/E 骨架家族数 | `>=3` |
| `main_axes` | 不同主轴数 | `>=3` |
| `evidence_modes` | 不同证据方式数 | `>=3` |
| `camera_distance_classes` | 整体/场景、中景、近景、微距等不同类别 | `>=3`，且含整体/场景与近景/微距 |
| `three_quarter_non_clean` | 非干净主图典型三分之四角度数 | `<=2`，连续重复 `0` |
| `centered_product_non_clean` | 非干净主图机械居中数 | `<=2`，连续重复 `0` |
| `repeated_structure_tuple` | 连续复用相同骨架家族+主轴+镜头距离+证据方式 | `0` |
| `component_images` | 成图实际出现任一组件形态的图片数；含未编号组件 | 7/8/9 张分别 `<=4/5/6` |
| `component_none_but_observed_component` | 策划为 NONE、成图实际出现组件形态 | `0` |
| `clean_main_observed_component_count` | 平台干净主图成图实际组件总数 | `0` |
| `hero_observed_component_count` | 营销首图成图实际组件总数 | `<=1` 且与策划一致 |
| `unplanned_text_images` | 成图出现 `allowed_text_exact` 之外文字的图片数 | `0` |
| `dimension_semantic_mapping_errors` | 数值绑定错误尺寸语义、边界或视角 | `0` |
| `role_filename_mismatches` | filename/slot/role 与成图实际角色不一致 | `0` |
| `same_component_same_position_consecutive` | 连续相同组件 ID 和位置 | `0` |
| `pte_complete_images` | 非干净主图具有完整 P/T/E 记录的数量 | 等于非干净主图数 |
| `prompt_complete_images` | 最终提示 16 个必填字段齐全的数量 | 等于非干净主图数 |
| `contact_sheet_reviewed` | 已检查全套联系表 | `true` |

批量任务分别填写计划批次统计和观察批次统计：`sku_count`、`planned_fingerprint_rows`、`observed_fingerprint_rows`、`planned_pairs_below_3_differences`、`observed_pairs_below_3_differences`、`identical_framework_sequences`、`normalized_prompt_duplicates`、`observed_topology_duplicates`。两类指纹行数都须等于 `sku_count`，其余重复/不足字段全部为 `0`。标准化比较须移除商品名、颜色、背景和场景名后，再比较实际 P/T/E、主轴、镜头、证据方式和组件位置。

机械统计只能拦截结构缺失，不能替代目视 QA；但机械统计未通过时禁止进入目视评分、继续批量生成或交付。可用 `scripts/validate_execution_manifest.py` 验证清单字段、唯一性和文件存在性，脚本通过不代表视觉通过。

## 逐张检查

### 1. 商品身份与事实

- 颜色、材质、结构、零件、开孔、边缘和比例是否与原图一致。
- Logo、标签、包装文字、销售数量和包装内容是否准确。
- 尺寸数字、单位和尺寸线是否与商品事实卡逐项一致。
- 卖点和宣称是否有用户确认的事实或证据。
- 人物动作、握持、穿戴和商品使用关系是否真实。
- 模拟状态、AI 来源和发布资格是否只记录在文件名、事实卡、策划卡、执行清单与交付报告中；用户未明确要求时，成图是否完全没有 `DESIGN PREVIEW`、`SIMULATED`、`NOT PUBLISHABLE` 或 `SIMULATED DIMENSIONS`。

任何不确定项视为未通过。

### 2. 主决策任务和信息密度

- 这张图解决的主要购买问题是否能用一句话说清。
- 主结论、视觉证据和从属信息是否服务同一个问题。
- 是否错误地把两个无关购买问题或多个同权重卖点挤在一起。
- 尺寸图的多项尺寸、步骤图的连续步骤和包装清单的多个物品是否仍属于同一任务。
- 遮住文字后，是否仍能看出当前图的信息任务或 SKU 专属证据。

“一图一个主任务”不等于“一图一个事实”。只有信息之间互相竞争、无法形成主次关系时才需要拆图。

### 3. 版式和移动端

- 商品是否为第一视觉主体。
- 商品区、文字区和证据区是否具有明确对齐或空间关系。
- 每张非干净主图是否有框架 ID、P/T/E、商品位置/占比/视角、主轴、视觉动线、有效留白、组件、字体层级和色彩比例记录。
- 标题是否只是填入剩余空白。
- 第一、第二、第三视觉焦点和视觉动线是否清楚。
- 是否标出了有效留白和无任务空区；平台干净首图以外，是否没有单个连续无任务空区接近或超过画面 30%。
- 左右结构的文字侧是否存在场景边缘、前景、动作轨迹、投影、材质母题、尺度参照或相连色面，而不是只有标题和大片空白。
- 按商品/动作 0.55、核心证据 0.25、主标题 0.15、从属信息 0.05 估算的加权重心是否位于中央 40%；偏出时是否有真实视觉配重和记录理由。
- 套图是否至少 4 张的第一视觉主体中心位于横向 38%～62%，并避免连续两张把主要重量压在同一角落。
- 在 180～240 px 缩略图下是否仍能识别商品和主要信息。
- 字体、信息卡、图标、边距和对比度是否一致且可读。
- 1024×1024 美式英文营销首图单行主标题是否通常达到 144～176 px且不低于 136 px，两行是否每行达到 112～140 px且不低于 108 px；后续卖点标题是否不低于 96 px。
- 营销首图必填价值说明是否通常为 50～68 px且不低于 48 px；所有营销图的卖点标签、状态、步骤和尺寸标签是否不低于 32 px，并在全尺寸下清楚可读。
- 是否检查了成图的实际可见占比，而非只相信提示词字号：单行主标题可见字高至少为画布短边 9.5%；两行每行至少 7.8%、整体至少 18%；副标题至少约 3.4%；主标题使用文字区约 62%～86% 的可用宽度。
- 主标题是否至少约为辅助说明的 1.8 倍、标签的 2.2 倍；是否避免所有文字整体偏小或同权重。
- 文案放不下时是否缩短文案、减少说明或重构版式，而不是等比缩小全部文字。
- 小卡片、圆形细节窗等组件是否确有信息任务，而不是为了填空；是否按成图实际形态统计，而不是只统计策划中的 C01～C08。
- 主标题是否最多 2 行；在最低字号下是否自然放下，而不是出现拥挤、极窄字宽、贴边或文字墙。
- 营销首图价值说明是否提供相对产品名称主标题的信息增量；若原文空泛，是否重写为具体价值而不是删除。颜色是否来自锁定色板、与主标题形成清楚从属并保持足够对比；不要求机械同色。
- 副标题如存在，是否与主标题形成同一标题组：1024×1024 实际字形净距 20～56 px、共享对齐方式、锚点偏差不超过约 24 px，并完整位于同一连续对比底面。
- 任意两个文字块的实际字形外框是否至少相距画布短边的 1.8%；即使文本框坐标没有相交，视觉上横向或纵向挤在一起也必须返工。
- 营销首图是否只有一条必填价值说明 `subtitle`；其他图是否把解释文案正确标为 `label/detail`，而不是做成第二主标题。
- 所有非平台合规图的证据表达是否遵守 [转化设计系统](conversion-design-system.md)：`label` 为 2～5 个英文词，`detail` 为 4～12 个英文词且最多 2 行；营销首图、卖点图、细节图或材质图是否至少有 1 组完整 `label + detail` 对，非首图无配对时是否拥有完整 `VISUAL_SELF_EVIDENT` 例外。
- 卖点、细节和材质图是否避免“只有大标题＋商品照”；若资料或画面不能支持事实说明，是否删除、改成中性可见描述或重构为视觉主导方案，而不是加入空泛形容词。
- 整套是否符合 [套图蓝图](image-set-blueprints.md) 的角色密度：至少 2 张营销图由场景、动作、材质或商品结构主导并保持 `component=NONE`，这些图仍可有 1～3 条直接证据说明；平台干净主图未计入配额，且没有把所有图片做成相同的小卡片模板。
- 文字包围盒连同描边、阴影和内边距是否完整位于 `T` 区及同一连续对比底面内；1024×1024 标题/副标题内边距是否至少 40 px、标签至少 28 px，与 `P/E` 外扩 40 px 安全遮罩零相交。
- 标题和副标题含 padding 后是否距画布四边至少 8%，标签至少 5.5%；是否没有通过削减 padding 来容纳大字。
- 斜切、不规则面板是否按实际内接安全区验收，是否没有单词跨越色块、照片窗或商品轮廓。
- 所有商品、背景、文字、数字、标线、卡片、圆窗、图标与装饰是否均由图像模型整图生成或整图编辑；是否完全没有脚本排版、外部叠字、程序化标线或像素合成。
- 标题与辅助文字的字形类别、视觉宽度、字重、大小写、字距观感、行距、对齐和标点是否符合字体视觉 DNA；颜色是否来自锁定色板且变化有对比度或层级理由。
- 英文主标题字距是否为 `0.00～0.04em`、词距是否至少 `0.30em`、两行净空是否至少 `0.14em`；是否完全没有横向压缩。
- 尺寸图是否逐项核对 `数值 → 尺寸语义 → 被测边界 → 所需视角 → 标签位置`；每个数字与单位是否紧邻唯一对应标线，字形外框距标线通常为 8～48 px，标线端点是否准确对应被测边界；是否没有把尺寸集中放到标题区或页脚。
- 尺寸图是否避免把 `SIZE`、`DIMENSIONS` 当作无信息增量的大标题；卖点与细节图是否避免只用 `FEATURES`、`DETAILS`、`TEXTURE` 等泛化标题。
- 平台干净主图是否无文字和组件；营销首图是否具有允许清单内的产品名称、必填价值说明、1～2 组证据表达及不超过 1 个已策划组件；场景图是否记录子类、信息增量、1 秒理解结论和文字决策，每张功能使用场景是否有一组贴近证据的 `label + detail`，且主画布可见动作和接触/摆放点；步骤图是否使用必要动作标签并可加入同任务详解。
- 尺寸图是否没有 `SIZE`、`DIMENSIONS`、`SIMULATED DIMENSIONS` 等无信息大标题；模拟状态是否只在非像素台账中记录，没有进入尺寸图画面。
- 最终整图提示是否具有 [转化设计系统](conversion-design-system.md) 的全部 16 个字段；字段值是否与已通过策划卡一致，而不是只写场景和风格；成图是否逐字核对 `allowed_text_exact`，未出现任何额外词句。

营销首图额外检查以下成图观察值，不能用提示词声明代替：

- 组件是否按策划为 `NONE` 或一个 C01～C08，且 `observed_component_count<=1`；若出现组件，其类型、区位、面积和证据任务是否与策划一致，没有未记录组件。
- 主标题是否逐字包含消费者能立即理解的通用产品名称，而不是只有品牌名、系列名、情绪口号或纯卖点短句。
- 必填价值说明是否补充一个核心卖点或使用结果，没有重复产品名；是否另有 1～2 组与可见结构、动作、参数或场景关系绑定的 `label/detail`，且至少一组完整配对。
- 能否在约一秒内识别商品及一个核心特性。
- 主标题是否位于上三分之一或侧中安全区。
- 主标题含 padding 后是否距四边至少 8%，完整避开底部 15%。
- 主标题是否没有位于商品正下方或形成全宽底部字幕条。
- 主标题块是否通常占画布高度 20%～32%、宽度 46%～68%，既没有缩在角落，也没有遮挡商品关键结构；例外是否有已确认设计理由。
- 是否具有区别于普通目录图的货架停止点。

### 4. 套图统一性与变化

- 商品身份、主辅色、光线、阴影、背景质感和文案语气是否统一。
- 2～3 个视觉签名是否在大多数非平台营销图中受控复用。
- 镜头角度是否按信息任务分配，而不是重复同一角度换背景。
- 非干净主图三分之四角度和机械居中是否各不超过 2 张且不连续；连续相同结构四元组是否为 0。
- 是否从机械统计确认：不同框架 ID 至少 4、骨架家族至少 3、主轴至少 3、证据方式至少 3、镜头距离至少 3。
- 每次框架应用是否记录至少 3 项相对静态示例的 SKU 专属变化。
- 7/8/9 张套图使用组件的图片数是否分别不超过 4/5/6，营销首图是否不超过 1 个组件、其他营销图是否不超过 2 个，且至少 2 张营销图保持 `component=NONE`、`evidence_dominant=true`。
- 单图组件数是否不超过 2；卡片总面积是否不超过 22%。
- 是否避免连续两张在同一位置复用相同卡片或圆形细节窗。
- 非平台营销图中“平背景 + 单个居中/三分之四商品 + 独立标题且无 E 区证据”的图片数是否为 0。
- 多视图是否会误导销售数量、变体或包装内容。
- 换成同品类任意 SKU 后若几乎无需重新设计，判定为通用模板失败。
- 除平台纯白/干净首图外，背景、文字、强调色、场景色温是否继承同一套色彩 DNA；联系表中是否像同一品牌系列。
- 批量任务是否先完成计划结构指纹分配表、生成后完成观察结构指纹分配表；两者行数均等于 `sku_count`，任意两套至少 3 个字段实质不同，且相同框架序列、标准化提示重复和成图拓扑重复均为 0。
- 对比图是否有真实竞品资料、明确参考物或同一商品可验证状态；是否只比较一个变量、保持同尺度同视角同光线，并避免竞品 Logo 与无法核验的“市场平均”。
- 联系表中重复字母的字形气质、双词词距、两行标题行距和对齐方式是否稳定；所有文字颜色是否来自锁定色板且变化有明确理由。

### 5. 市场和视觉符号

- 人物、场景、住宅、办公环境、道具、语言和单位是否契合具体市场与人群。
- 是否把国旗、地标、人物发色、黑金或霓虹当作本地化捷径。
- 若使用这些元素，是否与品牌、品类、场景、价格带和人群具有明确关系。
- 是否存在刻板人物形象、过度促销、舞台化假场景或明显 AI 质感。

### 6. 平台与发布资格

- Amazon MAIN 和 TikTok Shop 干净首图是否满足 [平台与发布规则](platform-rules.md)。
- 营销首图是否被错误当作禁止文字的第一张商品图。
- AI 纯生成或重绘商品身份的图片是否已在文件名、策划卡、执行清单和交付报告中明确标为设计预览，同时没有默认把该状态烧进图片。
- 视觉 QA 与发布资格是否分别给出结论。
- 图片是否为确认的画幅、分辨率、用途和版本。

## 零容忍失败项

出现任一项即返工，不进入设计评分：

- 商品身份、颜色、结构、数量、文字、Logo、数字或尺寸错误。
- 无依据宣称、错误平台用途或错误发布资格。
- 套图机械统计任一必填字段为空，或任何要求为 0 的字段不为 0；未制作全套联系表就判定通过。
- 用户未明确要求时，任一成图出现 `DESIGN PREVIEW`、`SIMULATED`、`NOT PUBLISHABLE`、`SIMULATED DIMENSIONS` 等模拟/不可发布状态文字；或把用户明确批准的披露计入商品信息文案。
- 任一非干净主图缺少框架 ID、P/T/E、主轴、视觉动线、镜头、文字角色、允许文字清单、证据绑定、组件、字体层级或色彩比例策划记录；最终提示 16 个必填字段不完整。
- 营销首图或卖点图没有非文字视觉证据。
- 遮住文字后只剩通用商品照。
- 标题与商品或证据没有结构关系。
- 平台干净首图以外存在接近或超过 30% 的连续无任务空区，或左右结构的一侧只有标题和大片空白。
- 加权视觉重心明显落在中央 40% 之外且没有真实配重，或连续图片把主要重量重复压在同一角落。
- 尺寸标签远离对应标线、集中放在标题区或页脚、对应关系含糊，或标线端点与被测边界不对应。
- 尺寸数字正确但绑定错误尺寸语义、错误商品边界或错误测量视角。
- 尺寸图使用 `SIZE`、`DIMENSIONS`、`SIMULATED DIMENSIONS` 等无信息大标题，或用披露替代尺寸数字和贴线关系。
- 营销首图标题进入底部禁区、贴边、位于商品正下方或形成底部横幅。
- 营销首图主标题没有通用产品名称，只出现品牌名、系列名、情绪口号或纯卖点短句。
- 平台合规主图出现任何从属组件；营销首图实际组件超过 1 个、其他营销图超过 2 个，或出现未记录的小圆窗、小卡片、芯片、标签、徽章或胶囊。
- 策划写 `组件：NONE`，但成图实际出现任何未编号组件形态；或组件预算只按策划 ID 统计而没有观察最终像素。
- 任一图片出现 `allowed_text_exact` 之外的卖点标签、小标题、规格、材质或口号；已策划且有证据的首图或后续图 `label/detail` 允许保留。
- 营销首图在移动端无法识别商品或主标题。
- 1024×1024 美式英文营销首图单行主标题低于 136 px、两行每行低于 108 px、副标题低于 48 px、后续卖点图主标题低于 96 px或标签低于 32 px，且无确认的等效字体度量理由；或成图实际可见字高未达到比例门槛。
- 主标题、辅助说明和标签整体偏小、层级接近，或缩略图中只剩无法辨认的文字灰线。
- 主标题超过 2 行、在最低字号下拥挤，或营销首图缺少有信息增量的必填价值说明。
- 首图标题与副标题的实际字形净距不在 20～56 px、对齐方式不同、锚点偏差超过约 24 px，或没有位于同一连续对比底面。
- 任意两个文字块的实际可见间距低于画布短边的 1.8%，形成相碰、粘连或并列拥挤。
- 其他图片把详解做成与主标题争夺层级的第二主标题；任一营销图的 `label` 不在 2～5 个英文词、`detail` 不在 4～12 个英文词或超过 2 行，说明远离证据、成为漂浮口号或在移动端不可读。
- `detail` 只写部件名，没有解释具体材料、结构、参数或可验证特征及其用户意义；或 `label`/`detail` 无法绑定画面中的具体证据。
- 把 `Soft & Comfortable`、`Fine Craftsmanship`、`Solid Materials` 等无依据形容词当作事实卡，或用视觉和资料无法支持的表达替代中性描述。
- 营销首图、卖点图、细节图或材质图只有“大标题＋商品照”；或所有图片都复用相同卡片模板。信息较多本身不失败，只有说明不可读、证据失联、层级竞争或组件遮挡才返工。
- 营销首图没有必填价值说明或至少一组完整 `label + detail`；卖点、细节或材质图没有完整证据对且没有完整 `VISUAL_SELF_EVIDENT` 例外；任一非干净主图仅有 headline。
- 套图少于 2 张 `component=NONE`、`evidence_dominant=true` 的营销图，把平台干净主图计入该配额，无字场景没有独立信息增量，说明组件覆盖商品关键部位、对齐不清、色彩或字体脱离整套系统，或没有任何必要的消疑角色。
- 任一功能使用场景没有贴近动作、接触、适配或摆放证据的 `label + detail`，主画布没有动作与接触/摆放点，或用状态小字、大标题、箭头、圆窗内动作、卡片墙替代该说明和证据。
- 套图少于 4 个框架 ID、3 个骨架家族、3 种主轴、3 种证据方式或 3 种镜头距离；三分之四/机械居中超过配额，或连续复用相同结构四元组。
- `产品居中/三分之四角度 + 换背景 + 独立标题` 且没有 E 区证据；只有换色、换背景、镜像或替换商品却声称是新构图。
- 无竞品资料或测试依据仍制作“我们的产品 vs 市面产品”，同时改变多个变量，或使用无法核验的优越性结论。
- 主副标题虽可使用锁定色板中的不同文字颜色，但层级混乱、对比不足、颜色冲突或像来自不同模板。
- 任何文字、描边或阴影越出 `T` 区、跨越其连续对比底面、进入商品/证据安全遮罩或覆盖关键结构。
- 标题/副标题内边距不足 40 px、标签内边距不足 28 px，或含 padding 后进入画布四边 8% 文字安全区；通过减少 padding 塞入大字同样失败。
- 非平台套图出现未在色彩 DNA 中定义的第二套主色系。
- 同套的字形类别、字宽、字重、大小写、字距观感、行距或对齐明显漂移，或文字颜色脱离锁定色板且无理由。
- 成品图使用脚本排版、外部文字层、程序化尺寸线、程序化组件或任何非图像模型的像素合成。
- 英文主标题负字距、词距小于 `0.30em`、两行净空小于 `0.14em`、横向压缩，或临时切换超窄字体。
- 通用换 SKU 模板。
- 批量任务未在生成前完成计划结构指纹分配表、生成后完成观察结构指纹分配表，存在差异字段少于 3、相同框架序列、标准化提示重复或成图拓扑重复。
- 生成结果按完成顺序、文件时间戳、目录枚举或“最新文件”推断归属，或文件名/slot/role 与成图实际角色不一致。
- 用户授权自主决策后，Agent 跳过三选一、逐图策划卡、结构分配或 QA，而不是记录选择理由后自行完成。

## 回归场景

使用以下场景验证 Agent 行为；它们是测试案例，不是需要在其他文档重复的工作规则。

### 信息确认

1. 用户只上传商品图：必须分别确认区域与平台、图片语言、视觉风格。
2. 推荐项展示后 Agent 直接继续：失败；推荐不等于确认。
3. 用户在三题推荐均已展示后回复“全部按推荐”：允许继续并回显摘要。
4. 缺少尺寸：不猜测，改用替代主题。
5. 用户要求未经证实的认证或绝对化效果：拒绝写入图片。

### 主决策任务

1. 尺寸图同时出现长宽高：允许，因为共同解决尺寸适配问题。
2. 步骤图出现 2～4 个连续动作：允许，因为共同解决使用方法。
3. 营销首图用商品识别、一个核心特性和视觉吸引共同建立点击兴趣：允许。
4. 同一张图同时讲便携、防水、承重和折扣：失败；拆成不同任务，且未经证实的内容删除。
5. 场景图因为有留白而加入无任务口号：失败；删除文字。

### 场景文字决策

1. 纯生活方式场景已经明确提供目标人群、真实比例和生活情境，相关功能也在其他图片解释：允许无字，并记录无字理由。
2. 滤杯架在杯口上的冲煮图是套图中唯一的功能使用场景，缩略图能看出冲煮但不易确认支撑关系：使用 `OVER-MUG SETUP` 与 `Three tabs rest across the cup rim` 的一条 `label + detail`，允许且优先。
3. 功能场景使用大标题、副标题和多个卡片重复同一动作：失败；压缩为一条贴近证据的表达。
4. 场景图因留白加入 `ENJOY EVERY MOMENT`：失败；口号没有信息增量。
5. 用平台干净主图加一张无字生活方式图，声称已满足 2 张 `component=NONE`、`evidence_dominant=true` 的营销图：失败；平台干净主图不计入配额，视觉主导图仍可有证据说明。

### 本地化符号

1. 美区商品默认加入金发模特：失败；人物选择必须来自目标人群和真实场景。
2. TikTok 商品默认使用霓虹：失败；平台名称不构成视觉理由。
3. 电竞设备使用与品牌匹配的受控霓虹：可以进入候选方向。
4. 珠宝或香水使用与价格带匹配的黑金：可以进入候选方向。
5. 使用国旗、地标或人物发色后，移除这些元素便没有任何本地化依据：失败。

### 营销首图与排版

1. 产品放在背景上，标题位于空白处，遮住文字后没有卖点证据：失败。
2. 标题可以随意移动到任何角落：失败；重建结构关系。
3. 主标题横贯商品下方或进入底部 15%：零容忍失败。
4. 提示词使用“沿产品底边”“沿托盘前缘”或“贴着下边缘”：失败；改用明确画布区位和对齐轴。
5. 商品清楚但没有货架停止点，像普通目录图：点击潜力未通过。
6. 营销首图加入一个连接真实细节的小圆窗，并配策划卡批准的 `label/detail`：允许；该圆窗必须从属、可读并强化同一核心价值，主商品仍是第一焦点。
7. 营销首图加入一个低权重规格芯片、状态标签或免责声明胶囊：有真实信息缺口且纳入唯一组件预算时允许；同时出现多个组件、无信息增量或取代主证据时失败。
8. H04 用于营销首图时把场景做成悬浮小卡片：失败；改为与画面边缘相连的大尺度场景分区。
9. 为容纳 8～12 个英文词，把营销首图标题缩到 72 px：失败；缩短为 2～5 词并恢复字号基线。
10. 主标题 96 px、辅助说明 48 px、标签 32 px，虽然可读但仍低于新首图基线且层级偏弱：失败；扩大首图主标题或删除低价值说明。
11. 主标题达到 100 px 但遮住商品关键结构并占据半幅：失败；调整区域关系，而不是用大字替代构图。
12. 主标题只写 `CONTROL THE POUR` 或 `BUILD YOUR GRID`，没有 `OIL DISPENSER` 或 `DRAWER ORGANIZERS` 等通用产品名称：失败；改为 `PRECISION OIL DISPENSER` 或 `MODULAR DRAWER ORGANIZERS`，原口号如需保留则降为副标题。
13. 主标题已含产品名称，价值说明再重复同一产品名或引入三个无关卖点：失败；重写为一个核心用户价值，并用 1～2 组 `label/detail` 证明同一价值，不能删除后退化为只有标题。
14. Amazon MAIN 或要求无营销文字的 TikTok Shop 干净首图为了满足产品名称规则而加字：失败；产品名称规则只适用于允许文字的营销首图/商品封面。
15. 提示词写了 `120 px`，但成图标题仍只占画布一小角：失败；按实际可见字高和文字区填充率返工，不能以提示词数字判定通过。
16. `FABRIC RESISTANCE BANDS` 被排成三行并占据约半幅，副标题又横贯全宽：失败；优先改为更短且保留品类名称的两行标题，并删除无必要副标题。
17. 标题一半在深色区、一半跨入商品照片区，即使仍能辨认：失败；缩短、改行或改框架，让完整文字包围盒留在同一连续对比底面。
18. 斜切深色面板的外接矩形看似容得下文字，但实际单词和副标题越过斜边：失败；按面板内接安全区重新排版。
19. 主副标题分别使用锁定色板中的白色与灰色或强调色：可以，但必须对比清楚、从属明确且组合统一；若颜色冲突、抢层级或像两套系统则失败。
20. `MINI / LABEL MAKER` 虽然只有两行且字号足够，但使用超窄字体、`LABEL` 与 `MAKER` 词距不足、两行相贴：失败；保留固定字体 DNA，恢复至少 `0.30em` 词距和 `0.14em` 行间净空，放不下则扩大 `T` 区或缩短标题。
21. 同一套图中一张使用窄体全大写、另一张使用普通宽度粗体、第三张字距明显变大：整套失败；用同一字体视觉 DNA 重写提示并通过图像模型重生或编辑受影响图片。
22. 图片模型把同一个字母 `A`、`M`、`R` 生成成明显不同字形，即使文案拼写正确：失败；只能让图像模型重生或编辑，禁止外部叠字修补。
23. 商品缩在右下角，左半边除标题外没有前景、场景结构、动作轨迹或证据，连续空区超过约 30%：失败；扩大并向中心移动商品，或加入与任务相关且连接 P/T/E 的真实配重。
24. 商品偏右但对侧由真实场景边缘、功能动作和标题共同形成闭合动线，加权重心仍在中央 40%：允许；不要求机械居中。
25. 尺寸标题写在左上角，全部数字列在左下角，而标线位于商品右侧：失败；让图像模型重做整图，把每个数字贴到对应标线中段或端点。
26. 标题字号达到 136 px，但字形离画布左边只有 28 px：失败；字号与至少 8% 四边安全区必须同时通过。
27. 为放下大标题把文字框 padding 从 40 px 减到 8 px：失败；缩短文案、扩大 T 区或更换框架，不得牺牲 padding。

### 框架选择

1. Agent 先识别主决策任务、商品形态和证据类型，再给出 3 个候选：通过。
2. 3 个候选只是同一框架换色、换道具或左右镜像：失败。
3. 候选没有说明适配理由、风险和至少 3 项 SKU 专属变化：失败。
4. 全库失配时使用 `X01` 并说明跳出原因：允许；不得自动写入正式库。
5. `X01` 未经 3 种不同商品形态验证就收录：失败。

### 可选组件

1. 后续 P01 卖点图使用一个连接真实接口的圆形细节窗：允许。
2. D01 使用一个尺寸芯片辅助主要尺寸线：允许。
3. 每张营销图都放三张相同小卡片：失败；组件不得成为默认模板。
4. 场景图无信息缺口仍加入空图标卡：失败；改为 `NONE`。
5. 一张图同时使用圆窗、三卡、胶囊、徽章和步骤条：失败；保留最必要的 1～2 个。
6. 连续三张在右下角复用相同证据卡：失败；改变证据方式或删除组件。

### 后续详解与对比

1. 营销首图使用一条锁定色板内的从属价值说明，并配置 1～2 组证据标签和详解；其他图用 `label/detail` 承载解释而不做成第二主标题：允许。
2. 后续细节图没有大标题，只在三个真实局部旁放 38～46 px 的短说明：允许；这些是 `detail`，不是副标题。
3. 每张图片都复制“大标题＋一行口号”而没有证据绑定：失败；改用与证据绑定的详解和短标签。允许信息丰富，但不得复制同一空洞层级。
4. 为每张图强制加入三张说明卡：失败；说明和组件都按信息缺口选择。
5. 同一商品 `OPEN / FLAT` 状态在同视角同尺度下对比：允许。
6. 没有竞品资料却制作 `OURS / ORDINARY` 并写 `BETTER QUALITY`：失败；删除或改做商品自身状态证明。
7. 首图副标题与主标题同色且字号合格，但相距 96 px 像另一条口号：失败；移动到 20～56 px 字形净距并共享对齐轴。
8. 细节图只写 `REINFORCED HINGE`，没有说明其作用：作为 `detail` 失败；改为如 `Wide hinge keeps the stand steady`，或降为低权重 `label`。
9. 8 图套图有 5 个卖点，但只有两张图解释证据，其余全是大标题：失败；至少重构 3 张图片为证据详解，并保留 2 张 `component=NONE`、`evidence_dominant=true` 的视觉主导图；视觉主导图仍可使用直接证据说明。
10. 鞋类细节图把 `Soft & Comfortable`、`Fine Craftsmanship`、`Solid Materials` 做成三个事实卡：失败；没有具体证据，不构成事实说明。
11. 画面清楚显示鞋口填充、双线缝合与纹理外底，分别标注 `Padded Collar — Cushions Around the Ankle`、`Double-Stitched Seams — Clean, Reinforced Edges`、`Textured Outsole — More Surface Contact`：允许；仍须核对原图和资料确实支持每项表述。
12. 细节图使用一个 2～5 词 `label` 加一条 4～10 词 `detail`：默认通过；至少一组完整配对是卖点/细节/材质图的角色门槛。配对可直接标注，不强制装进卡片；只有完整 `VISUAL_SELF_EVIDENT` 例外可免除。
13. 材质图为了统一版式复制前两张图的三卡模板，遮住商品关键纹理：失败；根据证据位置改成直接标注，并保留至少 2 张视觉主导低文字密度后续图。

### 30 款批量失败回归

1. 30 个 SKU 各有 7～9 张，但大量后续图没有商品信息：整批失败；更不得用 `DESIGN PREVIEW` 等状态小字填充画面或冒充文案，`visible_status_disclosure_images` 必须为 0。
2. 每套都有卖点、细节和材质图，但这些图片只有大标题：失败；逐图至少有一组完整 `label + detail`，或提交完整 `VISUAL_SELF_EVIDENT` 例外且不突破无字上限。
3. 任一功能使用场景以“低文字密度”为由无字，或只有静态商品加小圆窗：失败；每张功能使用场景必须有一组贴近证据的 `label + detail`，主画布还须显示动作和接触/摆放点。
4. 每套只在“居中商品”和“三分之四商品”之间切换背景：失败；框架 ID、骨架家族、主轴、证据方式和镜头距离统计必须同时通过。
5. 30 套提示的字段顺序相同不是问题，但移除商品名、背景色和场景名后，P/T/E、主轴、镜头、证据方式和组件位置仍完全相同：`normalized_prompt_duplicates>0`，整批不得生成或交付。
6. 批次只记录“每款换商品、换场景、换焦点”，没有计划与观察结构指纹分配表：失败；两者行数均须等于 `sku_count`，相近 SKU 至少 3 个指纹字段实质不同。
7. 用户说“中间问题自己决策，不用问”：Agent 仍输出并记录三候选、选择/淘汰理由、策划卡、文字覆盖统计、结构分配和 QA，再继续生成；若直接跳过则失败。
8. 单图看起来可接受，但没有全套联系表，无法发现角度、主轴和组件节奏重复：失败；`contact_sheet_reviewed=false` 时不得交付。
9. 一张尺寸图出现 `SIMULATED DIMENSIONS`，无论作为大标题还是小页脚都失败；模拟状态只写入非像素台账，尺寸数字仍须贴近对应标线。
10. 一套 8 张含 1 张干净主图，只有 5 张含商品信息文案、2 张非干净主图无字：失败；至少 6 张含商品信息文案，非干净主图无字最多 1 张。
11. 计划表的组件全部为 `NONE`，但成图自动加入圆形局部窗或事实卡：失败；组件按最终画面形态计数，逐张重做。
12. 并发生成按文件修改时间把结果分配给 SKU，导致 filename/role 与成图内容错位：失败；必须按每次工具返回值直接绑定原 `job_id`。
13. 计划结构指纹全部不同，但最终成图都退化为居中商品、右侧卡片和同一三分之四镜头：失败；观察结构指纹也必须通过差异门槛。
14. 营销首图策划了一个证据标签，但模型又加入未列入清单的 `STURDY STRUCTURE`：失败；首图标签和详解本身允许，只有逐字允许清单之外的文字或超出一个组件预算才是零容忍项。
15. 尺寸值均正确，但 `12.5 cm` 标到本体宽而非含把手总宽：失败；正确数字绑定错误语义边界仍须整图重做。

### 迭代闭环

1. 字体锁、标题组和套图清单均通过，但联系表仍有遮挡或视觉重心失衡：仍然失败；自动校验不能替代像素级视觉 QA。
2. 单张文字碰撞：只重排或重做该张；不得无理由重做全部商品身份。
3. 两张源图的结构、颜色或部件数量不一致：身份级失败；重做该商品的双角度源图、事实台账和全部受影响成图。
4. 模拟测试从单张想象出隐藏结构或性能卖点：事实级失败；只能使用双角度共同可见特征，并在事实卡、执行清单和 QA 报告中明确记录模拟约束，不在图片中加状态小字。
5. 每轮修复后重新检查全套联系表、逐字符文案、数字、商品身份和内容台账；零容忍项为 0 且点击潜力通过才结束。

### 生成与套图

1. 单张拼写、数字或局部元素错误：只返工该张。
2. 商品颜色或结构漂移：重新使用原始商品素材，不沿用错误成图。
3. 多数图片重复同一三分之四角度，只换背景：整套失败。
4. 独立多角度图没有新增任务或误导销售数量：删除或改为有明确任务的主题。
5. 批量 SKU 只替换商品、颜色和标题：所有模板图失败。
6. 多件套框架重复完整套装，造成销售数量误解：零容忍失败。
7. 20 个无关 SKU 使用同一框架序列、同一文字侧和同一组件位置：整批失败；先按商品形态、证据方式和购买疑虑建立结构指纹并重做分配。
8. 首图使用暖米色，后续图整体换成冷蓝灰且色彩锁中没有该色系：整套失败；后续图必须继承同一色彩 DNA。

## 交付结论

- 已通过、已返工和因信息缺失被替换的图片。
- 套图机械统计完整一行；批量任务附计划与观察批次统计及结构指纹分配表结论。

- 营销首图的一眼识别和标题安全区结论。
- 设计评分、零容忍门槛和点击潜力结论。
- 商品身份、事实、文字、尺寸、市场契合和套图统一性结论。
- 每张图的视觉 QA 与发布资格。
- 仍需人工复核的内容。

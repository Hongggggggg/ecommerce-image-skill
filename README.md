# 电商套图生成 Skill

generate-ecommerce-images 是一个面向跨境电商静态图片制作的 Codex Skill。它根据商品原图与已确认资料，为 Amazon、TikTok Shop 等平台规划、生成和验收完整商品套图。

该 Skill 强调商品事实、视觉证据、移动端可读性和跨图片一致性。目标不是简单制作“商品照片加标题”，而是建立一套能够依次完成商品识别、卖点说明、场景想象和购买疑虑消除的图片系统。

## 主要能力

- 规划平台干净主图、营销首图、卖点图、场景图和细节图。
- 制作尺寸、容量、尺码、兼容、步骤和包装清单图片。
- 根据商品形态和购买任务选择不同版式框架。
- 为批量 SKU 分配不同的结构指纹，减少模板化和同质化。
- 约束标题、副标题、卖点标签和详细说明的信息层级。
- 检查商品身份、参数、文字、尺寸标线、组件和场景证据。
- 输出联系表、执行清单、观察记录和 QA 结论。
- 区分真实商品任务与设计模拟测试，避免把模拟参数用于真实发布。

## 核心原则

### 1. 事实优先

所有尺寸、材质、容量、数量、认证、性能和功效宣称都必须有可靠依据。无法从商品资料确认的信息不得猜测，也不得用常见行业参数代替。

### 2. 图像模型整图生成

商品、场景、文字、数字、尺寸线、图标、卡片和装饰必须由图像模型在同一画面中生成或编辑。

套图成品禁止使用脚本排版、程序化绘图、后期叠字和像素合成。脚本只可用于事实整理、执行清单验证和机械检查，不得创建或修改成品像素。

### 3. 不限制有依据的卖点说明

营销首图和其他营销图片均可使用卖点标签、详细说明和证据标注。信息丰富本身不构成失败，只有文字不可读、证据失联、层级混乱或组件遮挡时才需要返工。

营销首图默认需要：

- 清晰的通用产品名称。
- 一条简短价值说明。
- 至少一组与可见证据绑定的“标签 + 详细说明”。

### 4. 模拟状态不进入图片

设计模拟测试必须在事实卡、执行清单和 QA 报告中记录模拟性质，但图片默认使用：

~~~text
DISCLOSURE:NONE
~~~

除非用户明确要求，否则成图中不得出现以下状态文字：

- DESIGN PREVIEW
- SIMULATED
- NOT PUBLISHABLE
- SIMULATED DIMENSIONS
- 其他模拟、AI 生成或不可发布提示

这些文字即使位于页脚、字号很小或拼写正确，也会被视为未计划文字并触发返工。

## 支持的图片类型

| 类型 | 主要用途 |
|---|---|
| 平台干净主图 | 满足平台对背景、主体和营销元素的要求 |
| 营销首图 | 建立商品识别、价值主张和点击兴趣 |
| 卖点图 | 用结构、动作或状态证明核心特性 |
| 细节/材质图 | 展示局部结构、触感、表面与做工 |
| 场景图 | 呈现真实使用关系、环境和目标人群 |
| 尺寸/容量图 | 将数字、单位和标线绑定到正确边界 |
| 步骤图 | 用 2～4 个连续步骤说明使用方式 |
| 包装清单图 | 清晰展示包装内实际包含的物品 |
| 有依据的对比图 | 对比同一商品状态或有事实依据的单一变量 |

## 标准工作流

~~~text
商品识别与事实卡
→ 确认市场、平台、语言和视觉风格
→ 确认图片类型与数量
→ 建立整套说服链路
→ 为每张图片选择框架和主决策任务
→ 完成逐图策划卡与结构指纹分配
→ 锁定视觉方向和商品身份
→ 建立 job_id 执行清单
→ 图像模型逐张整图生成
→ 记录实际成图结构和文字
→ 联系表、机械 QA、视觉 QA 与发布资格判断
~~~

## 安装

通过 SSH 克隆仓库：

~~~bash
git clone git@github.com:Hongggggggg/ecommerce-image-skill.git
~~~

如果网络环境需要使用 GitHub SSH 443 端口：

~~~bash
git clone ssh://git@ssh.github.com:443/Hongggggggg/ecommerce-image-skill.git
~~~

也可以仅将以下目录复制到目标项目：

~~~text
.agents/skills/generate-ecommerce-images/
~~~

## 使用方式

在包含该 Skill 的 Codex 项目中，可以直接提出类似请求：

> 使用 generate-ecommerce-images，根据商品原图制作一套面向美国 Amazon 的英文商品套图。先整理商品事实，再推荐图片类型并完成生成和 QA。

批量任务示例：

> 使用 generate-ecommerce-images，为这 3 个互不相关的商品分别制作 7 张套图。中间的创意选择自行决定，但必须完成结构指纹分配、逐图策划和最终 QA。

模拟测试示例：

> 使用 generate-ecommerce-images 生成 3 个虚构产品的模拟测试套图。模拟状态只写入事实卡和 QA 报告，不要出现在图片像素中。

## 建议提供的资料

- 商品名称和清晰的多角度原图。
- 已确认的尺寸、材质、容量、数量和包装内容。
- 核心卖点及其事实依据。
- 目标国家、平台、语言和单位体系。
- 目标人群、价格带和期望使用场景。
- 品牌 Logo、色板、字体或参考风格。
- 希望制作的图片类型、数量与顺序。
- 明确禁止出现的元素、文案或宣称。

资料不足时可以安全降低创意复杂度，但不得猜测尺寸、材质、性能、认证或效果。

## 发布说明

Skill 的 QA 结论不能代替平台审核、商标审查、法规审查或人工校对。

没有真实货架测试或 A/B 数据时，只能评价“点击潜力通过/未通过”，不得宣称已经提升点击率。设计模拟测试和虚构商品素材不得直接用于真实商品发布。
